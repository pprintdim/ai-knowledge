# Sitemap для OpenCart 3 — СТАНДАРТ для повноцінних магазинів

**Статус (2026-08-18): це обовʼязкова структура для кожної натяжки повноцінного
OC3-магазину (не ленду).** Еталонна реалізація — hydrophob.net, контролер
`catalog/controller/extension/feed/google_sitemap.php` + `sitemap.xsl` у корені
(копія XSL лежить поруч із цією нотаткою). Переносити в новий проєкт як базу,
підганяючи лише секції під сутності проєкту.

## Структура (фіксована)

```
/sitemap.xml                індекс (sitemapindex)
  /sitemap/pages.xml        маршрутні сторінки + інфо-сторінки
  /sitemap/categories.xml   категорії + їхні зображення
  /sitemap/products.xml     товари + ГОЛОВНЕ І ВСІ ДОДАТКОВІ зображення кожного
  /sitemap/posts.xml        статті блогу + обкладинки
  /sitemap/gallery.xml      медіа, якої нема в інших секціях: зображення теми + ВСІ відео
  /sitemap/style.xml        XSL-стиль (віддається контролером)
```

**Правило розподілу медіа: кожен файл рівно один раз.** Товарні зображення —
тільки в products, обкладинки — тільки в posts, категорійні — тільки в
categories. gallery.xml збирає решту (промо-кадри теми, hero-слайди тощо) і всі
відеокліпи. Жодних дублювань між секціями.

## Вимоги до вмісту

- **Динамічна генерація з БД** при кожному запиті — нові товари/статті/фото
  потрапляють у карту самі, без перегенерацій.
- **Прямі посилання на оригінали, НІКОЛИ через `image/cache/…`**: кеш чистять,
  після чого всі посилання з карти — 404 до перегенерації. Плюс `is_file()` перед
  додаванням: битий запис у БД не має тягти бота на 404.
- Зображення — `image:image` **всередині `<url>` сторінки-власника** (окремого
  "image sitemap" як типу не існує). Відео — `video:video` з обовʼязковими
  `thumbnail_loc`, `title`, `description`, `content_loc` (прямий .mp4), `duration`
  (секунди, 1–28800); `<loc>` — сторінка, де відео можна подивитись (вимога формату).
- Відео без осмисленого опису в карту не потрапляє (Google відкидає такі записи) —
  описи тримати в моделі `catalog/model/tool/video.php` обома мовами.
- hreflang-пари `xhtml:link` у контентних секціях; gallery їх не має — і XSL
  ховає колонку мов, коли в документі немає жодного `xhtml:link`.
- Форматований вивід (переноси/відступи) — інакше «все в один рядок» і замовник
  вважає файл битим.

## XSL-вітрина (sitemap.xsl)

Таблиця для людини: індекс → перелік розділів; секція → сторінки з розгорнутим
списком медіа (бейджі IMG / VIDEO / PREVIEW, прямі клікабельні посилання,
лічильники в шапці) + **кнопка «Показати XML (як бачить Googlebot)»** (fetch
поточного URL → сирий документ у <pre>). Перевіряти рендер через `xsltproc
style.xsl section.xml` — той самий рушій, що в браузері.

## Три граблі

**1. `&amp;` в `<loc>`.** `url->link()` екранує для HTML → у XML лишається
`&amp;`. Лікується `str_replace('&amp;', '&', $output)` перед addAlternates.

**2. nginx не знає `.xsl`** → `application/octet-stream`, браузер ігнорує стиль.
Без root віддавати стиль через сам контролер (`sitemap_section=style`,
`Content-Type: text/xsl`).

**3. Чисті URL без root:** правило nginx не потрібне — SEO-парсер
(`startup/seo_url.php`) сам розбирає `/sitemap/<name>.xml` →
`extension/feed/google_sitemap&sitemap_section=<name>`. У жодному посиланні
карти не повинно бути `?route=`.

**4 (бонус). Масовий resize у циклі карти = memory exhausted.** Саме тому
оригінали, а не `model_tool_image->resize()` на кожен файл.

## Не забути

- фід у `oc_extension` (type=feed, code=google_sitemap) + `feed_google_sitemap_status=1`,
  інакше `/sitemap.xml` — 200 і нуль байт (виглядає робочим!)
- `Sitemap: https://<домен>/sitemap.xml` у robots.txt
- вимкнені товари/сторінки випадають самі; після дедуплікації перевіряти
- валідацію робити XML-парсером (ET) від імені Googlebot, не grep-ом
