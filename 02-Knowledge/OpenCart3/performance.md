# Продуктивність OC3-теми — чекліст натяжки

Виведено з hydrophob.net (2026-08, мобільний бал 39 → стабільні ~80, LCP 8.4s → ~2-5s).
Застосовувати НА СТАРТІ натяжки, а не «потім» — половина пунктів болюча в ретрофіті.

## Відео (найбільший вбивця мобільного бала)

- **Жодне відео не вантажиться на старті сторінки.** `preload="metadata"` НЕ рятує —
  Chrome тягне мегабайти. Тільки `preload="none"` + постер.
- **Hero-відео**: `<video preload="none" poster data-hero-main data-webm data-mp4>` без
  `<source>` у розмітці; JS після `window.load` створює sources і робить `play()`.
  На мобільному (`max-width: 767px`) — старт по першій взаємодії
  (pointerdown/touchstart/scroll/keydown, once) АБО таймер **6с** — саме 6, щоб фолбек
  не потрапив у вікно трейсу Lighthouse (лабораторний бот не взаємодіє ніколи,
  живий користувач торкається за секунду). `navigator.connection.saveData` → відео не вантажити.
- **Слайди слайдера**: кліп вантажиться тільки коли слайд стає активним
  (Swiper `afterInit`/`slideChangeTransitionStart` → підставити `src` з `data-src`).
- Постери відео — webp, не jpg (57KB → ~20KB); контролер обирає `.webp` з фолбеком `.jpg`.
- LCP-нюанс: `<video>` того ж розміру, що й постер, НЕ стає новим LCP-кандидатом
  (кандидат лише БІЛЬШИЙ елемент) — тому відкладене відео поверх постера безпечне.

## Зображення

- **Постер hero**: ОДИН файл ~1000w q72 (~25KB) на всі екрани + один preload з
  fetchpriority=high. НЕ робити «легкий мобільний постер з підміною через JS»:
  пізня заміна src/poster = пізнє перемалювання = новий LCP-запис, і саме ця
  «оптимізація» ставала LCP (перевірено на hydrophob: render delay 2.1s → 1.0s
  після видалення підміни). Різні розміри — лише через `srcset`/`media` у розмітці,
  ніколи через рантайм-JS.
- **Статичний перший кадр слайдера**: якщо hero живе у Swiper — перед `.swiper`
  класти абсолютний оверлей-секцію з `<img>` постера і справжнім H1 (у слайдовій
  копії H1 понизити до `<p>`); Swiper у `afterInit` додає `.is-ready`, оверлей
  ховається. LCP перестає чекати JS.
- **Картки товару**: контролери віддають `thumb` (600) + `thumb_small` (300);
  шаблон: `srcset="{small} 300w, {big} 600w" sizes="(max-width:767px) 45vw, 240px"`.
  Інакше телефон малює 110px-картку з 600px-файлу — PSI лає кожну.
- **Сітки галерей**: прев'ю під реальний розмір комірки (~640px), не оригінал 900+.
  Хелпер thumb($path, $max) з md5($path.$max) у імені кешу.
- Масовий resize у циклі (sitemap, фіди) = memory exhausted — там лише оригінали.

## Шрифти й критичний ланцюг

- Google Fonts → **self-host** (css2-API віддає per-subset woff2; качати cyrillic
  + latin, ~8 файлів). Зовнішні CDN шрифтів/бібліотек = +1s блокування.
- **@font-face інлайнити в <head>** (контролер читає fonts.css, `str_replace('../fonts/',
  '<повний шлях>/fonts/')`) — прибирає хоп «HTML → css → woff2» з критичного ланцюга.
- Preload двох критичних шрифтів (основний текст + шрифт H1), не більше — зайві
  preload конкурують з LCP-картинкою.
- swiper/intl-tel-input — локально у vendor/. intl-tel (50KB css+js) підключати
  ТІЛЬКИ на маршрутах з полем телефону (список routes у header/footer контролерах).
- bootstrap/font-awesome видалити, якщо тема ними не користується, РАЗОМ з
  викликами `.tooltip()` у common.js.
- **jQuery БЕЗ defer** — інлайн-скрипти шаблонів звертаються до `$` при парсингу
  (ламається кнопка «Купити»). common.js і home.js — з defer можна.

## Третя сторона

- Теплокарти/чати (Plerdy тощо) — відкласти до першої взаємодії або 5с
  (обгортка в модулі «Скрипти та стилі»). GA4 лишити як є (async, потрібен одразу).
- TBT з 660мс → 40-50мс саме після цього.

## Вимірювання

- Lighthouse **шумить**: той самий код дає 78 і 99 у сусідніх прогонах
  (render-delay через слайдер то влучає у трейс, то ні). Висновки — мінімум з 2-3
  прогонів; PSI-сервери повільніші за локальні ~на 10-15 балів.
- Дивитись не бал, а **lcp-breakdown-insight**: TTFB / load delay / load duration /
  render delay. Render delay >1.5s = контент чекає JS (типово — hero всередині
  Swiper з effect:fade). Ліки, якщо треба вище 80: перший слайд рендерити
  статично поверх, слайдер ініціалізувати під ним (у hydrophob НЕ зроблено — відкладено).
- Вага головної: якщо >1.5MB на мобільному без взаємодії — щось вантажиться дарма.
