# Пастки OC3 — короткий довідник

Граблі, на які вже наступали. Поповнювати після кожного проекту.

## Twig/тема
- `{% include %}` не працює (ArrayLoader) → партіал = окремий контролер.
- Ключі load->language автоматично мержаться в twig (event `ControllerEventLanguage`) — «магічні» `{{ text_* }}` це норм.
- Блок-HTML не можна обгортати в `<p>` — браузер закриє його на першому блоці, структура «зникає».
- Шаблону нема в темі → тихий fallback на default (стоковий вигляд = забув створити файл у темі).

## Мови
- Глобальний мовний файл МУСИТЬ зватись `<code>.php` усередині теки мови — інакше `Language::get()` віддає самі ключі (ціни «600decimal_point00»).
- `oc_language` рядок другої мови на прод — легко забути; без нього перемикач мовчки скидає на дефолт.
- `getLanguages()` кешується — `rm system/storage/cache/cache.catalog.language.*` після змін.

## SEO
- `oc_seo_url.language_id`: рядки на КОЖНУ мову, інакше друга мова на index.php.
- Route-слаг ≠ назва фізичної теки web-root.
- 301-хук: тільки GET, не-AJAX, safe-list маршрутів; масиви в GET (category[]) імплодити.
- `{page}` плейсхолдер пагінації: rawurlencode ламає його в query — у twig replace обох варіантів або нести в path літералом.

## Checkout
- `guest/save` ставить shipping_address ЛИШЕ з `shipping_address=1` у POST.
- `shipping_method/save` падає без попереднього GET `checkout/shipping_method` (session quotes).
- Порядок: guest/save → GET ship → save → GET pay → save → GET confirm (створює order) → `extension/payment/<code>/confirm`.

## БД/права
- Права кастомних маршрутів: `permission LIKE '%route%'` бреше (json-екрановані слеші) → `JSON_SEARCH(permission,'one','route') IS NULL` + подвійний `JSON_ARRAY_APPEND` (access+modify), guarded.
- Категорії без `oc_category_path` = порожні стокові вибірки.
- Сесії OC3 у БД (`oc_session`), не у файлах — дебаг session-даних через SELECT.
- `Currency::format` бере decimal_point з мови — див. пастку глобального файлу.

## Деплой/шелл
- rsync БЕЗ `--relative` з files-from кладе все плоско в корінь.
- rsync `--files-from` НЕ копіює вміст директорій одним рядком — гітігноровані asset-теки окремими прямими rsync з trailing slash.
- zsh: `for x in $VAR` не сплітить (`${=VAR}`); цикли з curl глючать — окремі виклики або PHP.
- `git add -A` без `git status` = закомічені гігабайти materials/.
- `git checkout <old> -- шлях` при перейменованій теці створює файли за СТАРИМ шляхом.
- macOS iCloud-теки (Obsidian vault) недоступні терміналу без Full Disk Access.

## Агенти
- Прогрес агента, не записаний на диск, гине при session limit — інкрементальний запис обовʼязковий у промпті.
- «Success»-звіт агента ≠ файли на диску — завжди `ls`/`wc -l` перевірка.
- Codex sandbox `workspace-write` без мережі (SSH/деплой йому не давати).

## DIR_STORAGE на проді живе ПОЗА коренем застосунку

CloudPanel/безпечні інсталяції виносять сховище: `define('DIR_STORAGE', '/home/<user>/htdocs/storage/')` — НЕ `<app>/system/storage/`. Наслідки:
- чистити кеш руками через `rm -rf <app>/system/storage/cache/*` на проді = чистити ПОРОЖНЮ теку; справжні `cache.*`, `template/`, `modification/` — у `htdocs/storage/`
- симптом: зміна в БД «не застосовується» (напр. вимкнені валюти далі активні) — бо модель читає файловий кеш `cache.currency` зі справжнього DIR_CACHE
- правило: шляхи кешу ЗАВЖДИ читати з config.php (DIR_CACHE/DIR_STORAGE), не припускати; у власних кешах (page cache) використовувати DIR_CACHE, щоб адмінська кнопка чистила те саме місце
(зловлено на hydrophob.net 2026-08-30: три тижні деплоїв чистили не ту теку — рятувало лише те, що twig-кеш теми був вимкнений)

## Натяжка теми: що ламалось на realChem (2026-09)

### Адмінка
- **`{{ action|e }}` у формі = розлогін.** `url->link()` ВЖЕ повертає екрановану адресу; повторне `|e` дає `&amp;amp;user_token`, браузер шле параметр `amp;user_token`, токен не доходить → OpenCart кидає на логін. Симптом від користувача: «при збереженні викидає». Стокові форми пишуть `{{ action }}` без фільтра — копіюючи шаблон, не «покращувати» екранування. Те саме для `cancel`/`back`.
- Перевіряти збереження треба **реальним POST**, а не на око: залогінитись curl-ом, витягти всі поля з форми, надіслати. Інакше баг живе місяцями.
- Модуль зареєстрований у `oc_module`, але без пари контролер+шаблон+мова в панелі → клік по ньому в списку = помилка. Реєстрація в БД і редагованість — різні речі.
- Кастомний розділ без запису в `oc_user_group.permission` просто не показується в меню — виглядає як «не задеплоїлось».

### Дані й міграція
- **Стокові демо-дані лишаються всюди** і течуть у публічне: `config_telephone=123456789`, `config_address='Address 1'` → прямо в schema.org Organization; `config_logo=opencart-logo.png` → у листи й JSON-LD; групи атрибутів Memory/Technical/Motherboard/Processor. Чистити на етапі посадки, а не перед запуском.
- `oc_stock_status` після установки має рядки **лише для англійської**. Товар «немає в наявності» показує порожній текст обома робочими мовами.
- **Теги товарів (`oc_product_description.tag`) порожні за замовчуванням** — пошук не знаходить за синонімами («гідрофоб» не знаходить «нанопокриття»). Заповнювати мовно: ajax-пошук теми шукає по `filter_name`+`filter_tag`, сторінка пошуку підставляє `search` у `filter_tag` сама.
- Мігрували атрибути в `oc_product_attribute`, але шаблон продовжує парсити характеристики з HTML-опису → **ті самі дані показуються двічі**. Після міграції атрибути роблять головними, парсинг опису лишають фолбеком.
- `oc_seo_url.query` — формат **без префікса**: `information/faq`, не `route=information/faq`. З префіксом ЧПУ мовчки 404.

### Мови
- `$this->language->get('code')` **не повертає код мови** (`$_['code']` у мовних файлах зазвичай немає) — будь-яка перевірка `=== 'ru-ru'` у контролері завжди падає в else. Симптом: меню/підписи лишаються мовою за замовчуванням на всіх версіях. Лікується не перевіркою, а виносом рядків у мовні файли.
- **Детектор неперекладеного по літерах ї/є/і/ґ бреше**: «Головна», «Магазин», «Відео» пишуться тими ж літерами, що й російські слова. Надійний спосіб — порівняти значення uk і ru **попарно за ключем**: однакові кириличні рядки = кандидати на переклад (з поправкою на легітимні збіги: «Доставка», «Артикул», «Товар», «Бренд»).
- Місяці/відмінки, зашиті масивом у контролері, — типове джерело українських дат на російській версії.
- Контент модулів і сторінок у БД має власні мовні блоки — файли можуть бути перекладені, а сайт усе одно показує одну мову.

### Контакти й єдине джерело
- Телефон/пошта/адреса розповзаються по хардкоду в шаблоні, мовних файлах і налаштуваннях — і починають **розходитись між собою** (три різні телефони на одному сайті). Одразу заводити єдине джерело з адмінки; адреса й графік мусять бути мовними (`config_*[language_id]` через `serialized=1`), телефон і пошта — спільні.

### Асети й зовнішні залежності
- **Відео без faststart** (`moov` у кінці файлу) = чорний екран замість відтворення: браузер чекає на весь файл. Перевірка — позиція `moov` відносно `mdat`; лікується `ffmpeg -c copy -movflags +faststart` без перекодування.
- Бібліотеки з CDN переносити локально (CDN ріжуть корпоративні фільтри). **При переносі стежити за відносними шляхами всередині CSS**: файл із `build/css/` посилається на `../img/`; поклавши його в корінь теки, отримуєш 404 на спрайти (у intl-tel-input так зникають усі прапорці).
- Мобільні копії важких відео + підміна `src` серверною подією за User-Agent — безпечно, лише якщо nginx **не кешує HTML** (перевірити `fastcgi_cache` у vhost).

### SEO-обвʼязка
- Бойовий `robots.txt` зі стандартним `Disallow: /image/cache/` і `Disallow: /catalog/view/` **вбиває індексацію картинок і рендер сторінки** — Googlebot не бачить жодного зображення товару й не може виконати CSS/JS. Потрібні явні `Allow` для `/image/`, стилів, скриптів і теки фідів.
- Події стокових розширень (`advertise_google`) лишаються в `oc_event` після чистки і **вказують на видалений контролер** — висять у порожнечу мовчки, бо `Action::execute` ковтає виняток.
- Sitemap-розширення може бути «увімкнене» в коді, але без рядка в `oc_extension` + `oc_setting` віддає **200 і нуль байтів**.

### Інструменти діагностики
- **headless Chrome ігнорує `--window-size` для верстки** (рендерить на 500px) і застосовує його лише до кадру скріншота — «мобільний» скрін виглядає як обрізаний десктоп. Двічі приймав це за горизонтальний overflow сайту. Перевірка: заміряти на скріні елемент з відомою CSS-шириною.
- Перевіряти блокувальники треба **реальним uBlock у Chrome** (`--load-extension`) і порівнянням DOM, а не грепом фільтр-списків: саморобний матчер правил дає лавину хибних збігів на правилах виду `*$script,3p,from=…`.
- SQL-файли й дампи **не лишати у веб-доступних теках** (`catalog/view/theme/<theme>/`) — навіть коли nginx їх ріже, це питання часу.

### Дрібне, але дороге
- `$this->load->language($route)` **без присвоєння в `$data`** — шаблон отримує порожні тексти замість підписів; у стокових контролерах трапляється часто.
- Стокові total-панелі кошика (`glob controller/extension/total/*`) тягнуть bootstrap-розмітку з default-теми у власну верстку.
- API Нової Пошти віддає довідники (міста, відділення) **без ключа**, лише з нижчими лімітами — порожній `np_key` не ламає чекаут одразу, але вистрелить під навантаженням.
