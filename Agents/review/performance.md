# performance

- SQL: EXPLAIN повільних, індекси під WHERE/JOIN, N+1 (OC3-класика: getProduct у циклі — міряти, іноді неминуче через API моделі).
- Кеш: що вже кешує платформа (OC3 cache.*, Lightning у well) — не дублювати; інвалідація при змінах ([[common-bugs]]).
- Зображення: розміри/webp, OC3 `image/cache` resize, lazy loading.
- JS/CSS: не блокувати рендер, мінімум запитів, CDN-залежності (Swiper) — одна версія.
- Cron/імпорти: стрімінг замість память-цілком, батчі, лок від накладання запусків.
- API: кешувати відповіді де можна, не смикати на кожен pageview.
- Memory: unset великих масивів у довгих циклах, generator-и.

Міряти ДО і ПІСЛЯ (time/ab/query log) — без цифр оптимізація не рахується.
