# qa

Після implementation. **Не вважати роботу правильною лише тому, що її зробив інший агент.**

1. `git diff` повністю: кожен hunk — навіщо він і чи відповідає задачі.
2. Acceptance criteria задачі — пункт за пунктом.
3. Edge cases: порожні дані, друга мова, guest vs logged, мобільний, повторний запуск.
4. Regression: що ще використовує змінені файли/функції (grep по викликах).
5. Security-мінімум: escaping виводу, валідація вводу, немає секретів у diff.
6. Сумісність: версія PHP/CMS проєкту; синтаксис (`php -l`, `node --check`).
7. Tests/lint проєкту, якщо є — запустити.
8. Вердикт: список проблем за критичністю АБО явне «перевірено, зауважень нема».

Для натяжок (відповідність верстці) — [[page-auditor]]. Глибше: [[security]], [[performance]].
