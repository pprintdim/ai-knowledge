## Прод hydrophob.ua = OpenCart (з 2026-08-15)
- **Задеплоєно**: заглушку знято, на `hydrophob.ua` тепер живий OpenCart (тільки головна 1:1 з версткою, решта сторінок ще стара hp-* тема — свідомо, натяжка триває поетапно).
- БД на сервері: `hydrophobua-oc` (з дефісом, MySQL 127.0.0.1:3306), юзер `hydrophobua-oc` — пароль у `~/AI-Workspace/secrets/ACCESS.md` (дописати туди при наступній синхронізації). Дамп — з локальної `hydrophobua_oc` (MAMP 8889), лежить у `hydrophob.ua/html/backups/`.
- Конфіги `config.php`/`hp_panel/config.php` на сервері створені вручну (шляхи `/home/hydrophobua/htdocs/hydrophob.ua/`, HTTP(S)_SERVER `https://hydrophob.ua/`) — не деплояться з git (гітігноряться навмисно, креди).
- **Пастка 1 (rsync, повторення бага з .gitignore)**: `rsync --exclude=config.php` (без `/`) теж зачепив `system/library/config.php` (звичайний клас фреймворку) — той самий клас багів, що й з `.gitignore` раніше. На rsync exclude-патерни для `config.php` ЗАВЖДИ ставити `/config.php` і `/hp_panel/config.php` (анкоровані), інакше сайт падає з "Class Config not found".
- **Пастка 2 (nginx, критична)**: стандартний CloudPanel-vhost для НОВОГО сайту генерує `location / { proxy_pass http://127.0.0.1:8080; ... }` (зовнішній 443-блок проксі на внутрішній) + внутрішній 8080-блок з `try_files $uri $uri/ /index.php?$args;` — це ОК для sectional-PHP верстки, але для OpenCart НЕ вистачає SEO-декодування чистих URL (`_route_`). Робочий приклад — `hydrophob.net.conf`: внутрішній блок має `try_files $uri $uri/ @seo_url;` + `location @seo_url { rewrite ^/(.+)$ /index.php?_route_=$1 last; }`. Без цього блоку категорії/товари з SEO-слагами (301-редірект з `?route=...`) резолвляться в ПОРОЖНІЙ route → потрапляють у intro/home fallback-логіку, а не в реальний контент. **Для будь-якого НОВОГО OpenCart-сайту на CloudPanel — одразу перевіряти/додавати `@seo_url` блок**, не покладатись на дефолтний шаблон.
- Також: мій попередній edit (прибирання 301-редіректу на html.hydrophob.net) необережно замінив `location /` (мало бути `proxy_pass` на 8080) на наївний `try_files` — зламав PHP-виконання взагалі (403 directory forbidden). Урок: коли патчиш один шматок vhost — читати ВЕСЬ файл, не тільки сусідні рядки, бо CloudPanel-vhosts мають двоблокову proxy_pass→8080 архітектуру.
