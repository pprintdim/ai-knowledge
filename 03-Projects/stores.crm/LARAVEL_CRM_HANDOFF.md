# Завдання для наступного GPT: Laravel CRM усередині CloudPanel

## Головна вимога

Потрібно створити **повноцінну цілісну CRM на Laravel**, а не набір окремих модулів у коді CloudPanel. Менеджерська CRM працює окремо за адресою `https://46.224.100.254:8442/crm/`, без домену та без iframe. Поточна вкладка CloudPanel `https://46.224.100.254:8443/crm` залишається окремою суперадмінською сторінкою.

Поточна Symfony-сторінка — лише тимчасова заглушка. Її не слід розвивати у повну CRM.

## Рекомендована архітектура

- Розгорнути Laravel у `/home/storescrm/htdocs/`, використавши підготовлений nginx-vhost на порту `8442`.
- Зберегти URL-префікс `/crm`; зовнішнього домену поки не створювати.
- CloudPanel і standalone CRM повинні мати незалежну авторизацію.
- У Laravel зробити окремі облікові записи менеджерів, ролі та permissions. Тимчасовий nginx Basic Auth після появи Laravel-login видалити.
- Поточну кнопку CRM у шапці CloudPanel залишити тільки для `ROLE_ADMIN`; менеджери заходять напряму на порт `8442`.
- Врахувати роботу Laravel під URL-префіксом `/crm`: маршрути, Vite assets, cookies, redirects, CSRF та `X-Forwarded-Prefix` не повинні вести в корінь CloudPanel.
- Не змінювати `vendor` CloudPanel і не вбудовувати бізнес-логіку CRM у її Symfony-контролери.

## Робота з OpenCart

CRM повинна бачити всі OpenCart-магазини, підключені до цього сервера, навіть якщо в них різні версії, префікси таблиць або структура конфігурації.

### Актуальне рішення для першої версії

CRM читає дані напряму з MySQL-баз OpenCart. Вимога з розширеного початкового ТЗ про обов'язкові API-конектори, HMAC і заборону прямого DB-доступу **не діє на першому етапі**.

- Доступ лише через окремих MySQL-користувачів із правом `SELECT`.
- Усі дані у frontend ідуть через REST API Laravel; React не підключається до OpenCart напряму.
- Жодних write-запитів, імпорту або масових коригувань у першій версії.
- Детальна специфікація: `PHASE_1_READ_ONLY_DB.md`.
- Можливість майбутнього редагування закладається окремим write-контрактом, але не реалізовується й не активується зараз.

Основні розділи:

1. Загальний список магазинів і стан підключення.
2. Замовлення з усіх магазинів в одній таблиці з фільтрами та переглядом деталей.
3. Експорт замовлень і товарів.
4. Перегляд, створення та редагування товарів.
5. Перегляд і створення користувачів/клієнтів.
6. Масові операції з обов'язковим підтвердженням.
7. Журнал усіх змін: хто, коли, на якому сайті й що змінив.

Для кожного магазину використовувати read gateway/repository, а не розкидати SQL по контролерах. Реєстр підключень зберігати в БД Laravel; паролі шифрувати через Laravel encryption. Підключати бази користувачами лише з правом `SELECT`. Операції запису додавати окремо після тестування, з транзакціями, аудитом і резервним сценарієм.

Поточний `crm-scan-opencart.php` можна використати тільки для первинного discovery та перенесення знайдених підключень у Laravel. Не запускати сканування файлової системи на кожному HTTP-запиті.
